# Pre-v1 route-address migration

This fixture preserves twelve historical central-inspection route addresses and
moves each through its v1 intermediate address to a v2 semantic route key. Use it
to rehearse state-only migration before changing a caller that still contains
pre-v1 indexed route instances.

## What this demonstrates

- `aws_route.tgw_to_firewall_endpoint[index]` is the historical pre-v1 address
  for the six centralized-egress routes.
- `aws_route.connectivity_to_firewall_endpoint[index]` preserves the required v1
  intermediate address in each move chain.
- `module.routes.aws_route.this["central-egress-N"]` is the final v2
  caller-keyed address.
- `aws_route.tgw_to_firewall_endpoint_without_egress[index]` and its
  connectivity intermediate preserve the second six-route family.
- `routes = merge(...)` materializes all twelve final semantic keys so every move
  target exists in configuration.
- `acknowledge_external_route_table = true` keeps route-table lifecycle outside
  the migration fixture.

The move chain changes Terraform addresses only. Physical forward and return
route intent remains unchanged, and a safe plan contains no route delete or
replacement.

## Relevant configuration

The complete fixture is in [`main.tf`](./main.tf), with the full move catalog in
[`moved.tf`](./moved.tf). One representative two-step chain is:

```hcl
moved {
  from = aws_route.tgw_to_firewall_endpoint[0]
  to   = aws_route.connectivity_to_firewall_endpoint[0]
}
moved {
  from = aws_route.connectivity_to_firewall_endpoint[0]
  to   = module.routes.aws_route.this["central-egress-0"]
}
```

The corresponding final route declaration is generated by this literal loop:

```hcl
{
  for index in range(6) : "central-egress-${index}" => {
    route_table_id                   = format("rtb-%017x", index + 1)
    availability_zone                = "us-east-1a"
    acknowledge_external_route_table = true
    destination                      = { ipv4_cidr = format("10.%d.0.0/16", index) }
  }
}
```

## Prerequisites

- Capture and back up the real state before editing configuration.
- Replace deterministic IDs and CIDRs from the captured caller state.
- Preserve the exact historical index ordering for both six-route families.
- Rehearse against copied state and review every action.

## Run

```shell
terraform init
terraform validate
terraform plan -out=migration.tfplan
../../scripts/check-migration-plan.sh migration.tfplan approved-actions.txt
```

Continue only when the guard reports zero delete or replace actions and every
create, update, or forget action is exact and approved. Fixture validation does
not prove that a caller's historical ordering matches this catalog.
